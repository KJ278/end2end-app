# Developer Onboarding

## Development rules

1. Treat security documentation as part of the product, not as an afterthought.
2. Add tests with every security-sensitive change.
3. Keep private keys on client devices only.
4. Prefer audited libraries over handwritten primitives.
5. Review logs whenever adding operational events.

## Incremental workflow

The project advances one phase at a time. After each phase, implementation pauses for review and explicit approval before the next phase begins.
